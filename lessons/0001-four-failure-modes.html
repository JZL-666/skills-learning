一、换个视角：你其实每天都在见这 4 种失控

你是 Agent 工程师，先用你的主场语言来说：任何 Agent（包括给你打工的 coding agent）失控，逃不出这 4 种模式。 Matt 在 README.md 里逐一点名，且每一种都引用了一本经典名著背书：

三、随堂测验（即时反馈）

Q1 · 你让 coding agent "做一个用户登录功能"，它自作主张加了短信验证码、第三方 OAuth、找回密码三个你没要的模块。这属于哪种失控？

诚实！其实这题答案是模式一（misalignment，未对齐）——出错点在"动工之前"：你们从未对齐过需求边界。选这个选项说明你注意到了：好的判断需要先看全选项。正确防御：动工前先 grill-me。
你选了模式一？方向完全正确——这就是 misalignment（未对齐），防御手段是动工前 grill-me。（这道题的"正确答案"是个小陷阱，考你会不会先读完所有选项——AI 和人都容易抢答。）

Q2 · Agent 写完功能后自己补了测试，测试全绿，但功能其实是错的（测试是照着错误实现写的）。防御这种"作弊"的核心手段是？

✅ 正确。这就是 TDD 红-绿-重构的"先红后绿"：测试先于实现存在并且失败过，AI 就无法拿错误实现反推出必然通过的假测试。第 5 课会深入。
Code Review 和换模型都有用但防不住这个作弊——测试与实现出自同一次"记忆"，同错同绿。唯一的结构性防御：实现之前先写测试并看它失败（红灯）。这是失控模式三的核心药方。

Q3 · Matt 认为 AI 时代软件工程基本功（架构、测试、领域建模）的重要性发生了什么变化？

✅ 正确。README 结语："Software engineering fundamentals matter more than ever."——AI 加速写码，也同步加速架构腐烂；只有基本功扎实的人能踩住刹车。这正是你的使命的立论基础。
再想想 README 的结语："Software engineering fundamentals matter more than ever."——AI 加速写码的同时也加速熵增（模式四），所以基本功比以往任何时候都更值钱。
本课小胜利 你现在拥有了整个仓库的"目录索引"：4 种失控模式 → 4 类药方。 从下一课起，我们每拆一个 skill，第一个问题永远是——"它在防哪种失控？"
